# Localization (i18n)

Full i18n pass landed 2026-09-09. Every user-facing string is wrapped in `t()`;
the app switches language live from a picker in **Settings**.

## Stack & layout

- `i18next` + `react-i18next`. Locale JSON bundles live under `frontend/src/i18n/`
  (namespaced by feature). Language picker wired into Settings.
- **6 locales**: `en` (source, ~1123 keys) + `es` / `pt` / `fr` / `ko` / `tl`.
- Locale files bundle at **build time** → a language/key change needs a full
  `npm run ios` rebuild, **not** a Metro reload, to appear on device.

## Translation provenance (⚠️ before launch)

- `es/pt/fr/ko/tl` were **AI-generated by Claude in-context** (5 translator
  subagents, ~367 strings each), **not human-reviewed**. Good first pass, but
  need a **native-speaker skim before store launch** — especially theological /
  Bible wording. English + any pre-existing translations were left intact.

## How to check i18n completeness (deterministic, not eyeballing)

The reliable finder is a **deterministic scan**, not agent review:

1. Extract every `t('ns:key')` / `i18n.t('ns:key')` reference from code.
2. Diff against the **flattened `en` locale**. Any referenced key absent from
   `en` = a silent gap (renders the English fallback in every language).
3. Dynamic keys like ``t(`ns:x.${v}`, MAP[v])`` are **invisible** to that regex
   — check their fallback MAPs by hand.

This caught two whole classes earlier passes missed: (a) `t('ns:key','English')`
where the key was never in the locale (222 found), and (b) labels hiding in
arbitrary data/config objects (quiz prompts in `useQuizSession`, leaderboard
quotes, AI chat tags, relative-time via shared `formatRelativeShort`, mode labels).

## Pitfalls (all fixed, keep in mind)

- **Raw `${...}` in a locale value** — when backfilling a key from
  ``t('k', { defaultValue: `${x} cards` })``, do NOT copy the template-literal
  source into the JSON. i18next only interpolates `{{param}}`, not JS `${...}`,
  so it renders the raw expression on screen. Convert `${expr}` → `{{optionKey}}`
  matching the call's options object. Detect via grep for single-brace
  `/\$\{(?!\{)/` in locale values (note `${{price}}` = literal `$` + `{{price}}`
  is fine). This hit **31 keys** (streak line, counts, etc.) — commit `d95748e`.
- **Plurals** — the streak-day count uses i18next plural forms (`_one`/`_other`)
  rather than a manual `count === 1 ? …` — commit `1abaa0e`.
